# Wanke 运维与数据安全

## 1. 凭证与地域

Wanke 支持在“设置”页面保存视频服务配置，也保留环境变量作为部署级 fallback。真实凭证只保存在服务端 SQLite / `.env.local`，不要使用 `NEXT_PUBLIC_` 前缀。

环境变量示例：

```bash
DASHSCOPE_API_KEY=...
ALIYUN_MODELSTUDIO_WORKSPACE_ID=...

ALIYUN_ACCESS_KEY_ID=...
ALIYUN_ACCESS_KEY_SECRET=...
ALIYUN_REGION_ID=ap-southeast-1
```

Wanke 当前默认使用万镜一刻新加坡地域：

```text
RegionId: ap-southeast-1
Endpoint: yike.ap-southeast-1.aliyuncs.com
```

切回上海时使用：

```bash
ALIYUN_REGION_ID=cn-shanghai
```

默认不要同时手工填写 `ALIYUN_YIKE_ENDPOINT`；只有需要显式覆盖官方区域 Endpoint 时再配置。Wanke 不做上海/新加坡自动回退，避免跨地域任务、媒资与账户状态被静默混用。

建议给自用 AK 最小权限，测试完临时 AK 后轮换或删除。

> 已存在的 `.env.local` 不会被 Git 更新覆盖。UI 设置的优先级高于环境变量；`npm run doctor` 会同时读取当前 SQLite 设置和环境变量，不会再因为只在 UI 配置凭证而误报“未配置”。

## 2. 系统运行依赖

### Node.js

要求 Node.js 22+。

### FFmpeg / ffprobe

AI 视频本身在云端生成，不需要本地 GPU；但 **Project 最终成片**依赖：

- `ffmpeg`：统一编码、转场、声音/BGM、最终 MP4；
- `ffprobe`：视频时长、分辨率、FPS、音轨和最终文件校验。

裸机 Ubuntu / Debian：

```bash
sudo apt-get update
sudo apt-get install -y ffmpeg
```

`ffmpeg` Debian/Ubuntu 软件包会同时提供 `ffprobe`。

Docker：仓库 Dockerfile 已在 runner 镜像中安装 `ffmpeg`，使用 `docker compose up -d --build` 无需宿主机额外安装。

如果二进制不在 PATH，可配置：

```bash
FFMPEG_PATH=/path/to/ffmpeg
FFPROBE_PATH=/path/to/ffprobe
```

部署或升级后建议执行：

```bash
npm run doctor
```

Doctor 会检查 Node 版本、当前有效视频服务配置、数据目录写权限、FFmpeg 和 ffprobe。

## 3. 数据目录

默认：

```text
data/
  wanke.db
  wanke.db-wal
  wanke.db-shm
  inputs/
  outputs/
  mail-outbox/
```

- DB：任务、素材、Project / Shot、设置、请求、远端响应、结果元数据和成片记录；
- inputs：百炼本地图片直传的可重试短期源文件；
- outputs：自动/手动归档的视频结果，以及 Project 最终 MP4；
- mail-outbox：邮件服务未开启或未配置完整时留档的 `.eml`（**不会送达**，仅用于开发与排查）。
  留档文件里含有一次性链接原文，正式环境要把邮件服务配置完整，让它不产生留档。

不要把 `data/` 提交 Git。

### 本地图片生命周期

本地 JPG / PNG / WEBP 会保存为 `wanke-input://...` 短引用。只要仍有 Job request 引用该图片，删除页面临时选择不会物理删除源文件；相关 Job 全部删除后才允许清理。

### 素材删除语义

素材库删除时默认只移除 Wanke SQLite 索引，不主动删除已经生成的视频和历史成片。需要扩展工作流云端清理时，由对应 Yike 删除逻辑处理；不要把“从素材库移除”理解成强制物理删除所有云端文件。

## 4. 备份

最简单可靠的方式：停止 Wanke 后完整备份 `data/`。

Docker：

```bash
docker compose stop
cp -a data "data-backup-$(date +%Y%m%d-%H%M%S)"
docker compose start
```

`data/` 同时包含 SQLite、可重试本地输入、已归档结果和最终成片，因此只备份数据库并不等于完整备份作品。

## 5. 结果归档上限

默认单文件 2048MB：

```bash
WANKE_MAX_ARCHIVE_MB=2048
WANKE_ARCHIVE_TIMEOUT_MS=1800000
```

归档是流式的，不把整个视频载入 Node 内存。无效的数值配置会回退到安全默认值；超出限制会终止并清理 `.part` 临时文件。

快速创作的视频在远端任务成功后会尽力自动归档；用户点击“生成最终视频”时还会再次补归档。因此普通用户不需要把“先去任务中心手动保存”当成成片前置步骤。

## 6. 最终成片资源

当前成片链会把采用镜头统一为 H.264 / yuv420p / AAC，再处理转场、BGM/响度、字幕轨并生成最终 MP4。

默认：

```bash
WANKE_FFMPEG_TIMEOUT_MS=600000
WANKE_FFPROBE_TIMEOUT_MS=45000
WANKE_FFMPEG_PRESET=medium
WANKE_FFMPEG_CRF=20
```

小型 2C/4GB 服务器可以正常承担个人 1080P 成片；如果 CPU 较弱，可以把 `WANKE_FFMPEG_PRESET` 调成 `fast` 或 `veryfast` 换取更快编码。不要为了提升速度随意并发很多最终成片任务，FFmpeg 才是当前服务器侧主要 CPU/内存消耗来源。

## 7. SQLite

使用 WAL，适合当前单机/个人工作台的并发读写。Wanke 不需要 Redis；真正的视频执行状态在远端 Provider，SQLite 是本地控制面和历史记录。

Job 删除如果会改变 Shot 候选或当前采用版本，Wanke 会同步更新 Shot / Project 时间戳，使历史 MP4 正确标记为“旧成片”，不会把已经改变来源关系的旧视频冒充当前成片。

## 8. 状态查询与恢复

创作任务由**服务端 Worker** 推进（见 §12），不依赖任何浏览器是否打开。
页面打开时的自动续查与「刷新」按钮只是请 Worker 提前看一眼自己的创作，
节奏由服务端按轮询间隔决定，成员反复刷新不会变成上游查询风暴。

远端 Provider 如果临时返回 Wanke 尚未识别的状态：

- Job 不会从自动轮询队列消失；
- `pollable=false` 的明确不可查询任务除外；
- 未知可轮询状态会降低到至少约 30 秒一次查询，等待恢复为已知状态。
- 长期无法确认的创作**不会自动退款**：上游可能已经生成，额度保留并转人工确认，
  后台「异常与风险 → 待人工确认额度」里可见。

这可以避免 Provider 新增中间状态时，一次未知响应就让长任务永久停止追踪。

扩展工作流健康检查会分别探测 Core / Studio surface。健康检查通过只证明 AK、签名、地域和 API surface 可访问，不等于每个 AI 能力的会员资格已经开通；生成资格仍以真实提交结果为准。

## 9. 故障处理

### `Forbidden.MembershipRequired`

请求已经到达 Yike，但当前账号/地域对应会员资格不足。它不是普通 Endpoint 或签名错误。

### `MainAccountUserNotFound`

Studio surface 找不到当前地域的主账户实体。先确认万镜一刻产品已经在对应地域初始化/开通。

### 任务提交失败

任务记录保存在 SQLite 并标记 failed。快速作品可以直接在“我的作品”里重试；高级任务也可以在任务中心重试。

### 页面关闭

不影响已经提交到远端的任务：推进、超时收口、额度确认/退回、通知与结果归档都在服务端完成，
完成后会自动出现在任务中心并进通知中心（开了邮件偏好的还会收到一封邮件）。
重新打开页面只是让界面立刻拿到最新状态。

### 视频结果打不开

远端签名 URL 可能过期。快速创作结果会尽力自动归档；高级任务的重要结果仍建议保存到本机。已经过期且没有归档时，如果 Provider 不能重新提供有效 URL，只能重新生成或从云端媒资另行取回。

### 最终视频按钮失败并提示 FFmpeg / ffprobe

先执行：

```bash
npm run doctor
```

裸机安装 FFmpeg；Docker 用户重新构建当前镜像：

```bash
docker compose up -d --build
```

已经生成并归档的镜头不会因为补装 FFmpeg 丢失。

### Storyboard 部分镜头失败

先查看 `failedShots`，优先使用“续跑故事板”；不要马上复制整单重跑。

### 视频翻译一直显示待确认

这是明确能力边界：当前 Yike 2026-07-07 SDK 没有同版本 query model，该任务会标记 `pollable=false`，不会被未知状态恢复逻辑反复查询。到任务指定 OSS 输出目录检查结果。

## 10. 支付宝收款

### 上线前配置清单

在「管理后台 → 系统设置 → 支付设置」完成，全部字段都有面向运营的中文说明：

| 项目 | 要求 |
|---|---|
| 启用支付宝收款 | 配置完整并测试通过后再打开 |
| 支付宝环境 | 联调用「测试环境」，真实收款必须切到「正式环境」 |
| 应用编号 | 开放平台应用 APPID |
| 应用私钥 | 服务端保管，界面只显示掩码；数据库中以主密钥加密存储 |
| 支付宝公钥 | 用于校验异步通知；**仅支持公钥模式，暂不支持证书模式** |
| 收款主体 | 商家账号的 2088 编号；到账通知会核对，防止资金进错账户 |
| 支付结果通知地址 | 公网 HTTPS，指向 `https://<域名>/api/payments/alipay/notify`，不能要求登录 |
| 支付完成返回地址 | 建议 `https://<域名>/payment/result` |
| 订单有效时间 | 默认 30 分钟，超时订单由后台关闭，过期订单不会再发放权益 |
| 支付网关地址 | 留空即按环境使用官方网关；只在特殊网络环境下填写 |

配置完成后点「支付测试」。测试只查询一个不存在的订单号，不产生真实收款：
返回「支付宝连接正常」说明应用编号、私钥与网关都被接受；测试结果与时间会留在同一页面。

### 主密钥

`WANKE_MASTER_KEY`（或退化到 `AUTH_SECRET`）用于加密支付宝私钥等敏感配置。
**丢失或更换主密钥会让已保存的密钥无法解密**，此时后台显示「配置需要重新保存」，
必须重新录入。轮换时用 `WANKE_MASTER_KEY_PREVIOUS` 保留旧密钥一轮，先解密再重新保存。

### 支付故障处理

- **订单显示「需要确认」**：金额不符、收款主体不符、订单已过期或已关闭却收到钱。
  在「订单管理 → 查看详情」可以看到通知原文与原因；处理方式只有人工退款或人工补偿，
  系统不会自动发放，也不会自动退款。
- **用户付了钱但页面没变化**：让系统主动确认，「订单详情 → 主动查询支付结果」；
  用户侧「我的订单 → 支付结果」也会自动查询。查询与异步通知走同一条结算路径，不会重复发放。
- **未验签通知**：「经营概览」会显示条数，原始内容保存在 `payment_notifications`。
  偶发通常是配置了错误的支付宝公钥；持续出现要按可疑流量排查。
- **退款结果未知**：退款失败原因里出现「退款结果未知」时，先到支付宝商家后台核对这笔
  退款请求号，确认后再点「重试退款」。重试使用同一个退款请求号，支付宝会去重，
  系统也不会重复回收权益。
- **对账**：收入以 `payments`（`status='success'`）为准，权益变动以 `quota_ledger`
  （幂等键 `order:<订单 ID>`）为准，过程证据在 `order_events` 与 `payment_notifications`。

## 11. 邮件（验证邮箱与找回密码）

### 上线前配置清单

在「管理后台 → 系统设置 → 邮件」与「基本设置」完成：

| 项目 | 要求 |
|---|---|
| 网站访问地址 | **必填**。邮件里的验证与找回密码链接使用这个地址，例如 `https://wanke.example.com`。留空时退化为使用请求来源，在反向代理下存在 Host 头被伪造的风险 |
| 启用邮件通知 | 配置完整并测试通过后再打开 |
| 邮件服务器地址 / 端口 | 465 一般配「使用 SSL 连接」，587 一般关闭并走 STARTTLS |
| 使用 SSL 连接 | 与端口匹配；开启后直接建立加密连接，关闭时在服务器公布 STARTTLS 时自动升级 |
| 发件人地址 | 支持 `Wanke <no-reply@example.com>` 写法，中文显示名会自动编码 |
| 邮件登录账号 / 密码 | 密码以主密钥加密存储，界面只显示掩码；留空账号表示不登录 |
| 验证邮箱邮件模板 / 找回密码邮件模板 | 可留空使用内置模板；占位符 `{name} {site} {link} {minutes} {contact}` |
| 注册后必须验证邮箱 | **只有在邮件真的能发出去之后再打开**，否则未验证会员无法创作也拿不到链接 |

证书校验使用系统信任链，项目内不提供「跳过校验」开关。自建邮件服务器使用内部 CA 时，
用 `NODE_EXTRA_CA_CERTS=/path/to/ca.pem` 把 CA 加进信任链，不要关闭校验。

### 三种投递结果

`email_messages` 记录每一次尝试，`status` 只有四种：

| status | 含义 | 会员看到 |
|---|---|---|
| `sent` | SMTP 服务器已经接收（`transport='smtp'`） | 「验证邮件已发送到 xxx」 |
| `outbox` | 邮件服务未开启或配置不完整，正文留档到 `data/mail-outbox/*.eml` | 「平台邮件服务尚未开启，暂时无法发送验证邮件，请联系客服」 |
| `failed` | 连接失败、证书校验失败、登录失败、收件人被拒或响应超时 | 「发送失败，请稍后重试；一直失败请联系客服」 |
| `queued` | 正在发送（进程崩溃时可能残留） | — |

技术原因只写入 `email_messages.error` 与服务器日志，不会返回浏览器。
`email_messages.body_text` 里的一次性链接会被替换成 `token=<已隐去>`：流水足够运营排查，
但即使数据库泄露也拿不到可用的验证或重置链接（`account_tokens` 只存摘要）。
「经营概览 → 异常与风险」显示 24 小时发送失败数、最后一次失败原因、邮件服务状态与未验证邮箱账号数。

### 故障处理

- **用户说收不到验证邮件**：先看 `email_messages`。`outbox` 是配置没开或不完整；
  `failed` 看 `error`；`sent` 让用户检查垃圾邮件箱，并确认发件域名的 SPF/DKIM。
- **忘记配置 `site_url` 就开了强制验证**：链接会指向用户当前访问的地址。补上 `site_url` 后
  让用户在「账号设置 → 验证邮箱」重发一次，旧链接会立即失效。
- **重置链接被转发给他人**：链接一次性且 30 分钟过期；重新申请会让旧链接立即失效；
  重置成功会退出该账号的全部登录。
- **限流**：同一账号同一用途 60 秒内只能发一封，接口回 429 并告知等待秒数；
  找回密码对不存在的邮箱同样按 60 秒节流，但响应与成功时完全一致，无法用于枚举账号。

## 12. 后台创作调度（Worker）

创作任务在**服务端**推进：查询在飞任务 → 写回真实状态与结果 → 终态时确认或退回额度（只一次）
→ 通知/邮件 → 快速创作结果自动归档。成员关掉网页、断网、换设备都不影响。

### 两种调度方式

| 方式 | 怎么开 | 适用 |
|---|---|---|
| 进程内循环（默认） | 什么都不用做，Node 服务启动即拉起；`WANKE_DISABLE_WORKER=true` 可关闭 | 单实例部署，最省事 |
| 外部调度（cron/systemd） | `WANKE_DISABLE_WORKER=true` + 配置 `worker_token`，按自己的节奏调用 `scripts/worker-tick.mjs` | 需要把调度纳入现有运维体系，或多实例只想让一台推进 |

两条路径跑的是**同一份 Worker 代码**，同一进程内一轮推进串行执行；多进程共用一个库时靠任务认领的
乐观锁保证同一条创作不会被两个调度同时查询与结算。

```bash
# 外部调度示例（每分钟一轮）
WANKE_WORKER_TOKEN=<令牌> WANKE_BASE_URL=https://wanke.example.com node scripts/worker-tick.mjs
```

### 上线前配置清单

- [ ] 后台「系统设置 → 后台任务」确认**启用后台任务调度**已打开（关闭时只有成员手动刷新与管理员手动推进）。
- [ ] 按上游建议设置每轮间隔（百炼异步视频建议 20–60 秒）与每轮任务数。
- [ ] 设置**创作超时时间**：超过这个时长仍未完成的创作按平台原因关闭并退回额度。
- [ ] 设置**连续查询失败上限**：查询抖动不会判死创作，达到上限才按平台异常关闭。
- [ ] 用外部调度时配置 `worker_token`（`openssl rand -hex 24`）。**留空则 `/api/internal/worker` 直接 404**，
      这是失败关闭：宁可让 cron 报错，也不留一个无鉴权的推进入口。
- [ ] 后台「系统设置 → 创作成本保护」核对同时创作数上下限、单次批量上限、每分钟与异常高速阈值；
      免费/付费用户分别有每分钟上限。
- [ ] 后台「系统设置 → 成本与毛利」填写**每秒视频内部成本**；填 0 表示暂时不知道真实成本，
      后台只会显示预估，不会把预估伪装成实际成本。

### 运行状态在哪里看

- **管理后台 → 经营概览**：Worker 面板给出是否启用、最后一次推进时间、距今秒数、连续失败轮数、
  当前积压、连续查询失败的任务数、24 小时超时数、24 小时待人工确认额度数、cron 令牌是否已配置；
  也可以在这里手动推进一轮。
- **`worker_runs` 表**：每一轮推进的触发方式（`scheduler`/`cron`/`admin`/`browser`）、
  起止时间、处理量、成功/失败/超时数、确认与退回笔数、通知与邮件条数、归档数、错误摘要。
- **`guard_events` 表**：每一次被拦截的提交（类型、原因、当时的数量/上限、套餐、时间）。
  被拦的提交不会留下计费行，没有这张表就看不见一次刷量。

### 额度收口语义（运维必须知道的规则）

| 创作结果 | 计费单 | 额度 |
|---|---|---|
| 成功 | `settled` | 预扣转为最终消耗，不再变动 |
| 平台原因（超时、连续查询失败、上游服务异常） | `refunded` | 原路退回（先退回本周期套餐额度，再退回加油包额度），只退一次 |
| 内容无法生成 / 上游状态无法确认 | **保持 `reserved`** | **不自动退回**——上游可能已经生成，转人工确认后再决定 |
| 提交阶段就被拒（未真正开始生成） | `voided` | 预扣释放 |

重复推进、Worker 重启、成员反复刷新都不会二次扣费或二次退回：额度只通过计费单的当前状态迁移，
通知与邮件都带去重键。

### 故障处理

- **任务一直卡在「等待开始/正在生成」**：先看 Worker 面板的「最后一次推进时间」。
  没有推进记录 → 调度没跑（进程内循环被关闭、或 cron 没配/令牌不对）。
  有推进记录但任务不动 → 看 `jobs.attempts` 与 `details.pollError`，通常是上游查询在报错。
- **`/api/internal/worker` 回 404**：`worker_token` 没有配置（失败关闭）。回 401 是令牌不对。
  `scripts/worker-tick.mjs` 在这两种情况下都会以退出码 1 结束，cron 会留下记录。
- **成员说额度被扣了但没出结果**：查这条任务对应的计费单。`reserved` 且任务已失败 →
  多半属于「内容无法生成/状态无法确认」，需要人工判断后处理，不要直接改库退款；
  `reserved` 且任务还在飞 → 等超时收口，或核对创作超时时间是否设得过长。
- **成本一直是「暂无成本数据」**：`cost_per_video_second_cents` 是 0，或上游没有返回真实时长。
  这是如实标注，不是故障；填写每秒内部成本后新的创作就会记为实际成本。
- **想临时停掉自动推进**：后台关闭「启用后台任务调度」即可，**不需要重启服务**
  （Worker 每轮重新读取设置）。管理员手动推进与成员刷新在此期间仍然可用。
