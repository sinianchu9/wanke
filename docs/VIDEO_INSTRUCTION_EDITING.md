# Wanke 整条视频编辑（Instruction Video Editing）

本功能解决的问题是：**已有一条短视频，希望通过文字指令和可选参考图修改视频内容、背景、风格、动作或镜头。**

当前实现使用百炼 Wan 2.7 Video Editing。

它不是 Retake，也不是传统时间线剪辑器。

## 1. 为什么不叫“局部重做 / Retake”

当前公开 API 可以：

- 添加 / 删除 / 修改视频中的内容；
- 修改背景；
- 修改视觉风格；
- 修改动作或镜头运动；
- 通过参考图片告诉模型服装、商品、道具或视觉元素应该变成什么。

但是当前公开请求参数里没有：

```text
start_time
end_time
mask
区域坐标
时间段替换
```

因此 Wanke 不会把：

```text
“整条视频指令编辑”
```

包装成：

```text
“重做第 3–5 秒”
```

只有以后接入真正可验证的时间段 / mask 能力，Wanke 才会新增独立 Retake 功能。

## 2. 当前底层请求

```text
model = wan2.7-videoedit
media[0] = 原视频
media[1..4] = 可选参考图片
prompt = 编辑要求
```

Wanke 当前限制：

```text
原视频：2–10 秒
参考图：0–4 张
输出：720P / 1080P
声音：保留原声音 / 自动处理
```

输入视频必须仍有百炼可以访问的 HTTP/HTTPS 云端 URL。

## 3. 独立 JobKind

视频编辑使用：

```text
JobKind = video_editing
```

它不塞进普通 `video_generation`。

原因：

- 输入是已有完整视频；
- 编辑语义和生成语义不同；
- 当前只走已验证的百炼 Video Editing；
- 它应该有独立父子关系和失败原因。

任务中心显示：

```text
视频编辑源自：原任务
```

## 4. 使用入口

```text
任务中心
→ 打开一条已完成的视频结果
→ 编辑这个视频
```

当前允许来源：

- AI 视频生成结果；
- 视频延长结果；
- 上一次视频编辑结果。

所以可以形成：

```text
生成
  ↓
编辑 A
  ↓
编辑 B
```

每一步都是新任务，不覆盖上一步结果。

## 5. 纯文字编辑

不提供参考图时，只输入修改要求。

示例：

原视频：

```text
人物在晴天街道上行走
```

编辑要求：

```text
把整体环境改成雨夜霓虹街道，保持人物身份、主要动作和镜头运动尽量不变。
```

这属于：

```text
整条视频视觉 / 环境编辑
```

不是：

```text
只修改某一个时间段
```

## 6. 参考图编辑

参考图片用于给模型更明确的目标外观。

典型用途：

- 换衣服；
- 换商品；
- 换道具；
- 替换某种视觉元素；
- 给出目标风格参考。

示例：

```text
原视频：人物穿黑色外套
参考图：米白色针织衫
Prompt：把人物外套替换成参考图里的米白色针织衫，人物身份、动作、背景和镜头尽量保持不变
```

Wanke 支持：

```text
本地 JPG / PNG / WEBP
公网图片 URL
```

本地图片先保存为 Wanke 短引用，真正提交百炼时才转成 Base64。

## 7. 与主体卡的关系

当前视频编辑界面没有直接把主体卡自动展开进去。

这是刻意的第一阶段边界。

主体卡属于：

```text
生成前身份控制
```

视频编辑的参考图属于：

```text
这一次编辑的目标外观
```

例如要把视频里的商品换成“金色手环”，当前直接上传金色手环参考图最清楚。

后续如果接主体卡，应作为“选择参考图片来源”的便利入口，而不能改变 Video Editing 的底层语义。

## 8. 与高级复刻的关系

### 视频编辑

```text
一个已有视频
→ 一条编辑指令
→ 新视频
```

适合快速修改。

### 高级复刻

```text
原视频
→ 视频拆解
→ 复刻脚本
→ 独立渲染
→ 新视频
```

适合可检查、可替换多个生产元素的完整复刻流程。

因此：

```text
视频编辑 ≠ 高级复刻
```

不要因为二者都能“改视频”就合并成一个模糊入口。

## 9. 与快速复刻的关系

快速复刻是万镜一刻现有业务流程，围绕：

- 原视频 MediaId；
- 商品替换；
- 用户素材；
- 数字人 / 声音；
- 字幕等生产参数。

视频编辑则是百炼模型级指令编辑。

当用户已经知道要做结构化商品 / 人物替换流程时，可以继续使用快速复刻。

当用户只想：

> “把这个视频改成这样”

则视频编辑更直接。

## 10. 与“结果继续创作”的关系

### 继续创作

把旧视频作为 `reference_video`，产生另一条新创作。

核心是：

```text
参考旧视频，再创作
```

### 视频编辑

把旧视频作为“需要被修改的主体视频”。

核心是：

```text
修改这条视频本身
```

这两个功能不能共用同一个按钮。

## 11. 与视频延长的关系

### 视频延长

```text
旧视频 = first_clip
→ 时间轴继续往后
```

### 视频编辑

```text
旧视频 = 被编辑视频
→ 整条内容按指令改变
```

延长强调：

> 接下来发生什么？

编辑强调：

> 这条视频应该改成什么样？

## 12. 与 Recipe 的关系

视频编辑不会重新应用 AI 视频生成 Recipe。

Recipe 是生成阶段“怎么拍”的策略。

视频编辑已经有一条具体视频作为输入，所以当前控制来源是：

```text
原视频
+
编辑 Prompt
+
可选参考图
```

重新把“产品广告 / 电影镜头”等 Recipe 注入，会让“编辑”与“重新生成”边界混乱。

## 13. 与 Provider Router 的关系

当前视频编辑属于功能专属能力：

```text
视频编辑
→ 百炼 Wan 2.7 Video Editing
```

即使基础生成设置为“强制万镜一刻”，视频编辑仍只在百炼 Key 已配置时开放。

原因和原生视频延长一样：

> 已核实的能力不能被基础 Provider 偏好覆盖，更不能自动回退到语义不同的 API。

## 14. 声音设置

第一阶段提供两个选择：

### 尽量保留原声音

```text
audio_setting = origin
```

适合：

- 只改画面；
- 希望保留原对白 / BGM / 环境音。

### 交给模型自动处理

```text
audio_setting = auto
```

适合编辑内容变化较大、希望模型同步处理音频的情况。

## 15. 操作演示 A：换衣服

```text
1. 任务中心打开成功视频
2. “编辑这个视频”
3. 上传米白色针织衫参考图
4. Prompt：把人物的黑色外套替换成参考图里的米白色针织衫，人物身份、动作、背景和镜头尽量保持不变
5. 声音：尽量保留原声音
6. 开始视频编辑
```

结果作为新的 `video_editing` 子任务出现。

## 16. 操作演示 B：改环境风格

```text
1. 不上传参考图
2. Prompt：把白天街道改成雨夜霓虹街道，保持人物身份、行走动作和镜头运动
3. 开始视频编辑
```

## 17. 操作演示 C：换商品

```text
原视频：人物手持黑色产品
参考图：目标金色产品
Prompt：把人物手中的黑色产品替换成参考图中的金色产品，保持手部动作、人物和其他场景尽量不变
```

这是模型级直接编辑。

如果业务需要“旧商品名 / 新商品 / 商品知识 / 多素材”等结构化生产控制，则应使用快速复刻或高级复刻，而不是把这些字段重新塞进视频编辑。

## 18. 失败边界

### 输入视频超过 10 秒

当前 Wan 2.7 路线不提交。

Wanke 不会默默截成前 10 秒后说“整条编辑成功”。

### 视频 URL 过期

属于输入素材不可访问。

### 参考图超过 4 张

UI 和服务端都阻止。

### 本地参考图

提交时转换为 Base64；Job 仍保存本地短引用，因此失败重试可以重新准备。

删除任务时，现有本地输入引用清理机制继续生效。

### 用户写“只修改第 3–5 秒”

Wanke 不会声称能精确执行这个时间范围。

界面已经明确提醒：当前是整条视频编辑。

## 19. 当前明确不做

- Retake 时间段选择；
- mask 涂抹；
- 像素级 inpaint；
- 自动分割人物 / 商品；
- NLE 时间线剪辑；
- 指定第几帧开始 / 结束；
- 用 `duration` 假装时间段编辑；
- 未核实的万镜一刻自动回退。

## 20. 验收标准

- [x] 独立 `video_editing` JobKind；
- [x] 使用 Wan 2.7 Video Editing；
- [x] 服务端限制输入 2–10 秒；
- [x] 参考图最多 4 张；
- [x] 支持纯文字编辑；
- [x] 支持本地 / 公网参考图；
- [x] 支持保留原声音 / 自动声音；
- [x] 任务父子关系清楚；
- [x] 与继续创作、视频延长、Recipe、高级复刻、快速复刻边界明确；
- [x] 页面内有使用说明和演示；
- [x] 不把整条编辑冒充 Retake。
