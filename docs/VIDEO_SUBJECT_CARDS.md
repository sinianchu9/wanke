# Wanke 主体卡：人物 / 产品身份层

主体卡解决的问题是：**同一个人物或产品会反复用于不同视频，不应该每次重新寻找并选择同一组参考图。**

主体卡不是模型，不是 Recipe，不是 Prompt 模板，也不是项目。

## 1. 一张主体卡是什么

主体卡由以下内容组成：

```text
主体名称
主体类型：人物 / 产品
身份描述
使用说明
1 张主参考图
0–4 张辅助参考图
```

当前上限为 5 张图片。

主体卡当前只接受图片，不接受视频和音频。

原因是它承担“稳定身份”的职责，不承担动作、镜头或时序参考职责。

## 2. 为什么有主参考图

主参考图代表这张卡最可信、最标准的身份。

展开主体卡进入生成任务时，Wanke 会把主参考图排在这张卡的第一位，再加入辅助图片。

主参考图不是“权重参数”，Wanke 当前不会伪造 Provider 未公开的参考权重。

## 3. 主体卡与素材库的关系

素材库回答：

> 这个文件是什么？

主体卡回答：

> 这几张图片共同代表谁 / 哪个产品？

正确流程：

```text
素材库
  ↓
保存人物 / 产品图片
  ↓
主体库
  ↓
把同一主体的 1–5 张图片组织成身份卡
```

主体卡不复制图片文件，只记录素材库引用。

### 删除素材时

如果素材库删除一张被主体卡引用的图片：

- 普通辅助图：从卡中自动移除；
- 主参考图：从卡中移除，并把剩余第一张图升为主参考；
- 如果已经没有任何图片：主体卡自动删除。

这样不会留下“看起来存在、实际上没有身份素材”的坏卡。

## 4. 主体卡与生成方式的关系

当前主体卡只接入：

```text
AI 视频
→ 保持人物 / 产品一致
```

也就是 `reference_to_video`。

它不会出现在：

- 描述生成；
- 单图“让图片动起来”；
- 首尾帧过渡。

原因：主体卡可能包含多张图片，本质上是多参考身份输入。

## 5. 主体卡与 Recipe 的关系

这是最重要的边界。

主体卡回答：

> 谁 / 什么产品？

Recipe 回答：

> 这条视频应该怎么拍？

因此：

```text
人物卡 ≠ 人物一致 Recipe
产品卡 ≠ 产品广告 Recipe
```

Wanke 可以在界面提示建议，但不会自动替用户切换 Recipe。

例子：

同一张“品牌女主角 A”人物卡可以用于：

```text
人物一致 Recipe → 强调身份稳定
电影镜头 Recipe → 强调电影构图和光影
短视频主镜头 Recipe → 强调 5 秒快速建立主体
```

身份相同，拍法可以不同。

## 6. 主体卡与 Prompt 的关系

主体卡不会自动把“30 岁女性、短发……”之类内部描述拼进 Prompt。

`description` 和 `usageNotes` 目前用于：

- 人工识别；
- 使用提示；
- 后续项目组织。

实际生成身份由选中的参考图片承担。

这样避免内部管理描述污染模型 Prompt。

用户 Prompt 应该主要描述：

```text
主体做什么
在哪里
镜头怎么动
环境 / 光线 / 氛围
```

而不是反复重新描述主体长相。

## 7. 主体卡与 Provider Router 的关系

主体卡进入任务前会展开成普通图片参考：

```text
主体卡
  ↓
主参考图 + 辅助图
  ↓
reference_to_video medias[]
  ↓
Recipe 执行策略
  ↓
Provider Router
  ↓
百炼 / 万镜一刻 / 对应模型
```

Provider 不需要理解“主体卡”这个 Wanke 产品概念。

这是有意的架构设计：主体卡属于 Wanke 产品层，而不是把某一家 Provider 的私有概念写进核心数据模型。

## 8. 参考数量规则

主体卡展开后的每一张图片都计入统一的多参考上限。

例如：

```text
人物卡 A：3 张图
产品卡 B：2 张图
```

合计已经是：

```text
5 / 5
```

此时不能再加本地图片、素材库视频或公网 URL。

如果选择主体卡会导致超过 5 个参考，Wanke 会阻止选择并明确提示。

### 去重

如果主体卡已经包含“正脸.jpg”，素材列表里这张图会显示为“主体卡”提供，不能重复添加。

同一个素材不会因为“主体卡 + 单独勾选”被发送两次。

## 9. 可以同时使用人物卡和产品卡吗

可以，只要总参考数不超过 5。

典型用途：

```text
人物卡：品牌女主角 A（2 张图）
产品卡：黑色智能手环（3 张图）
```

然后 Prompt：

```text
女孩在办公室抬起手腕看向手环屏幕，镜头从侧面缓慢推近。
```

这时：

- 人物 / 产品长相来自主体卡；
- 动作和场景来自 Prompt；
- “怎么拍”来自 Recipe；
- 百炼 / 万镜一刻由 Provider Router 决定。

## 10. 人物卡使用演示

准备素材：

```text
女主角-正脸.jpg
女主角-侧脸.jpg
女主角-全身.jpg
```

操作：

```text
1. 素材库添加三张图片
2. 主体库 → 新建主体卡
3. 类型：人物
4. 名称：品牌女主角 A
5. 选择三张图片
6. 主参考图：女主角-正脸.jpg
7. 创建主体卡
8. AI 视频 → 保持人物 / 产品一致
9. 选择“品牌女主角 A”
10. Recipe 选择“人物一致”
11. Prompt：女孩从办公室走向窗边，转身看向镜头
12. 生成
```

## 11. 产品卡使用演示

准备素材：

```text
手环-正面.jpg
手环-侧面.jpg
手环-佩戴.jpg
```

操作：

```text
1. 创建产品卡“黑色智能手环”
2. 主参考图选“手环-正面.jpg”
3. AI 视频 → 保持人物 / 产品一致
4. 选择“黑色智能手环”
5. Recipe 选择“产品广告”
6. Prompt：产品置于深色桌面，镜头缓慢环绕并推近屏幕
7. 生成 3 个版本
```

这里主体卡、Recipe 和批量版本各自承担不同职责：

```text
主体卡 = 产品身份
Recipe = 广告拍法
批量版本 = 候选数量
```

## 12. 与“继续创作”的关系

直接从主体卡生成的任务会在 Wanke 请求记录中保存 `_subjectCardIds`，用于说明该任务直接引用了哪些主体卡。

如果之后选择“以这个结果继续创作”：

```text
主体卡图片
  ↓
第一条视频结果
  ↓
把第一条结果视频作为新的 reference_video
```

此时新任务不再声称自己“直接使用主体卡图片”。

Wanke 会把原主体关系转成 `_sourceSubjectCardIds`，表示它们属于来源血缘，而不是当前直接输入。

这个区别可以避免项目关系越来越复杂时元数据失真。

## 13. 当前明确不做

本阶段不做：

- 自动人脸识别；
- 自动判断两张图是不是同一个人；
- 自动裁脸；
- 自动给人物 / 产品打权重；
- 主体 LoRA 训练；
- 主体专属模型训练；
- 人物卡自动选择“人物一致”Recipe；
- 产品卡自动选择“产品广告”Recipe。

这些能力以后可以独立增加，但不能破坏“身份层”和“创作策略层”的边界。

## 14. 验收标准

主体卡功能只有满足以下条件才算闭环：

- [x] 有独立主体库；
- [x] 人物 / 产品类型明确；
- [x] 1–5 张图片限制；
- [x] 主参考图明确；
- [x] 素材删除后引用自动修复；
- [x] 多参考模式可以直接使用主体卡；
- [x] 主体卡图片计入统一 5 个参考上限；
- [x] 与单独素材自动去重；
- [x] 不自动改变 Recipe；
- [x] 不决定 Provider；
- [x] 页面内有使用说明和演示；
- [x] 文档明确与素材库、Recipe、批量版本、继续创作的关系。
