# Wanke 批量版本与生成队列

本功能只解决一个问题：**同一个创作意图，一次生成 2–4 个独立候选版本。**

它不是“多段视频”、不是“多个不同 Prompt”、也不是某个 Provider 的 `n=4` 输出包装。

## 1. 用户入口

位置：

```text
AI 视频
→ 生成方式
→ Recipe
→ Prompt
→ 素材
→ 画面设置
→ 生成几个版本？
```

可选：

```text
1 个版本
2 个版本
3 个版本
4 个版本
```

`1 个版本`继续使用原来的单任务逻辑。

`2–4 个版本`进入批量提交逻辑。

## 2. 业务逻辑

用户选择 3 个版本时，Wanke 实际执行：

```text
同一份创作输入
    ↓
生成 Batch ID
    ↓
版本 1/3 → 创建独立 Job → 提交 Provider
    ↓
版本 2/3 → 创建独立 Job → 提交 Provider
    ↓
版本 3/3 → 创建独立 Job → 提交 Provider
    ↓
三个 Job 各自在远端排队 / 生成
```

Wanke 按 1→N 顺序发送“提交请求”，避免瞬间对同一 Provider 产生一组并发提交。

**注意：Wanke 只顺序提交，不会等待版本 1 完整生成结束后才提交版本 2。** 视频生成本身仍由远端异步执行。

## 3. 什么保持一致

同一个 Batch 中，以下内容必须一致：

- 生成方式；
- Recipe；
- Prompt；
- 参考素材；
- 画幅；
- 时长；
- 清晰度；
- 当前 Provider 路由规则。

版本之间的差异来自模型生成本身的随机性或 Provider 内部生成差异。

## 4. 什么不能用批量版本解决

以下需求不要使用批量版本：

### 不同 Prompt

错误示例：

```text
版本 1：男人在东京
版本 2：女孩在巴黎
版本 3：汽车在纽约
```

这是三个独立创作任务，不是一个 Batch。

### 不同产品或人物

如果每个版本需要不同参考素材，也应该分别创建任务。

### 连续三段视频

批量版本没有时间顺序，也没有前后镜头关系。

需要连续故事时使用故事板或后续的 Project / Shot 流程。

## 5. 与 Recipe 的关系

Recipe 决定“怎么拍”。

批量版本决定“同样的拍法要几个独立候选”。

例如：

```text
生成方式：让图片动起来
Recipe：产品广告
图片：黑色手环产品图
Prompt：镜头缓慢环绕产品，突出屏幕和表带质感
版本数：3
```

三个版本都会遵守“产品广告”的稳定策略。

批量功能不会为版本 2 自动换成电影镜头 Recipe，也不会为版本 3 修改 Prompt。

## 6. 与 Provider Router 的关系

批量版本不决定使用百炼还是万镜一刻。

每个版本提交时仍经过现有 Provider Router：

```text
Batch
  ↓
独立 Job
  ↓
Recipe 执行策略
  ↓
Provider Router
  ↓
百炼 / 万镜一刻
```

如果当前设置为“强制百炼”，同一批次全部按强制百炼执行。

如果当前设置为“自动”，每个独立 Job 都执行同一套自动路由规则。

## 7. 与任务中心的关系

每个版本是真实 Job，不合并成一个假任务。

任务中心显示：

```text
新品广告 · 版本 1/3
新品广告 · 版本 2/3
新品广告 · 版本 3/3
```

详情页会显示“批量版本 1/3”，并提供同批次版本切换。

每个版本可以独立：

- 排队；
- 生成；
- 完成；
- 失败；
- 刷新；
- 重试；
- 保存结果；
- 删除。

## 8. 失败边界

### 某一个版本提交失败

只把该版本标记失败。

Wanke 继续提交后续版本，不取消整个 Batch。

例如：

```text
版本 1/3：已提交
版本 2/3：失败
版本 3/3：已提交
```

这是合法状态。

### 某一个远端生成失败

只影响该版本。

用户可以进入该版本点击“复制参数重跑”。

重试会创建新的子 Job，不覆盖原失败记录。

## 9. 使用演示

目标：给一张手环产品图，一次生成三个广告候选。

操作：

```text
1. AI 视频
2. 选择“让图片动起来”
3. Recipe 选择“产品广告”
4. 选择黑色手环产品图
5. 输入：镜头缓慢环绕产品，屏幕亮起，突出表带和屏幕质感
6. 可选：智能增强提示词
7. 画幅选择 9:16
8. 时长选择 5 秒
9. “生成几个版本”选择“3 个版本”
10. 点击“生成 3 个版本”
```

预期结果：

```text
任务中心
├── 新品广告 · 版本 1/3
├── 新品广告 · 版本 2/3
└── 新品广告 · 版本 3/3
```

完成后逐个查看，挑选最好的结果。

## 10. 与下一阶段“继续创作”的关系

批量版本解决：

> 我还没有选中最终结果，先给我几个候选。

继续创作解决：

> 我已经看中了某一个结果，以它为起点再做新的创作。

因此正确流程可以是：

```text
生成 3 个批量版本
    ↓
选择版本 2
    ↓
继续创作
    ↓
再来一个类似版本 / 修改 Prompt / 使用结果作为新参考
```

“继续创作”不是“批量版本”的一部分，也不是“重试”。
