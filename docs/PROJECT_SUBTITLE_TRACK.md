# Project Subtitle Track

## 定位

Project 字幕属于最终成片层，不属于单个 Shot 或生成 Job。

当前稳定链路：

```text
Shot 定稿
  ↓
统一画面 / 音频结构
  ↓
Shot 顺序时间线
  ↓
项目 BGM / LUFS 母版
  ↓
Project SRT 字幕轨
  ↓
最终 MP4
```

## 第一阶段为什么使用可选择字幕轨

当前实现将 SRT 封装为 MP4 `mov_text` 字幕轨，而不是直接烧录到画面。

原因：

- 不依赖服务器字体；
- 不要求 FFmpeg 编译 `libass`；
- 不会因为字体缺失导致整个成片失败；
- 字幕可以保留为独立轨道，支持的播放器中可开关；
- 后续做烧录字幕、字体、描边和逐字高亮时仍可复用同一份时间轴。

这是“字幕轨”阶段，不是“字幕视觉设计器”。

## Project 设置

每个项目保存：

- `enabled`：是否在下一次成片中加入字幕；
- `content`：规范化后的 SRT；
- `language`：字幕语言代码，默认 `zho`；
- `title`：MP4 字幕轨名称；
- `updated_at`。

项目删除时字幕设置随项目一起删除。

## SRT 校验

保存时会：

- 去除 BOM；
- 统一换行符；
- 重新编号；
- 把时间分隔符统一成逗号毫秒；
- 校验每条字幕有开始/结束时间；
- 校验结束时间晚于开始时间；
- 校验每条字幕有文本；
- 最多 1000 条；
- 最多 100000 字符。

标准示例：

```srt
1
00:00:00,500 --> 00:00:02,500
第一句字幕

2
00:00:03,000 --> 00:00:05,500
第二句字幕
```

## 成片时再次校验

保存 SRT 并不代表项目时长已经确定。

真正装配时会再次检查：

- 所有 Shot 是否已定稿；
- 最终项目预计时长；
- SRT 最后一条结束时间是否明显超出项目时长。

当前允许最多约 2 秒容差，用于不同封装/帧率造成的小量时长差异。

如果字幕时间明显超出成片，会拒绝生成，而不是静默截掉字幕。

## MP4 封装

字幕阶段读取已经完成 BGM / LUFS 处理的 `audio-master.mp4`，然后：

- 视频：`copy`，不再次编码；
- 音频：`copy`，不再次编码；
- SRT：转换为 `mov_text`；
- 写入语言 metadata；
- 写入字幕轨 title；
- 输出最终 Project MP4。

所以添加字幕轨本身不会让视频再经历一次有损转码。

## 历史成片记录

每次 assembly 的 `settings_json` 会保存：

- 字幕是否启用；
- 语言；
- 轨道名称；
- cue 数量；
- 规范化 SRT 的 SHA-256 哈希。

不会把完整 SRT 再复制到每条历史成片记录，避免数据库记录无限膨胀。

修改 Project 当前字幕不会改写已有 MP4。

## 当前明确不做

第一阶段没有：

- 字幕烧录；
- 字体选择；
- 字号；
- 描边 / 阴影 / 背景框；
- 逐字高亮；
- 卡拉 OK 时间标签；
- AI ASR 自动生成字幕；
- 自动翻译字幕；
- 每个 Shot 独立字幕文件。

这些应该建立在稳定 Project 字幕时间轴之后，而不是和第一版字幕轨一起堆入 FFmpeg。
