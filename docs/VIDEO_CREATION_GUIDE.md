# Wanke AI 视频生成：功能边界、关系与使用说明

本文档只描述“AI 视频”主入口。目标是让每个功能都有明确职责、明确输入输出，并且知道它和其他功能是什么关系。

## 总原则

Wanke 把视频生成拆成四层，任何新功能都应该先归属其中一层，避免边界模糊：

1. **生成方式（Input Mode）**：决定素材规则，例如文生视频、单图生视频、首尾帧、多参考。
2. **生成预设（Recipe）**：决定创作策略和默认参数，例如产品广告、人物一致、电影镜头。
3. **提示词智能增强（Prompt Assistant）**：只整理文字描述，不改变素材、生成方式或 Provider。
4. **Provider / Model 路由**：负责百炼、万镜一刻及具体视频模型的执行选择。

关系如下：

```text
用户素材 + 用户描述
        ↓
生成方式：确定素材合法边界
        ↓
生成预设：确定“怎么拍”与稳定要求
        ↓
可选：提示词智能增强
        ↓
Provider 路由：确定“谁来执行”
        ↓
任务中心：跟踪结果、失败与后续创作
```

**重要：生成预设不会切换 Provider，Prompt 智能增强也不会切换 Provider。**

# 功能 1：生成方式

生成方式解决的问题是：**你手里有什么素材？**

## 1.1 描述生成

### 什么时候用

没有参考素材，只想通过文字生成一个新视频。

### 输入

- 文字描述
- 可选画幅、时长、清晰度

### 不接受

- 图片参考
- 视频参考

### 演示

输入：

```text
一辆黑色跑车晚上经过城市街道，路面有霓虹倒影。
```

操作：

```text
AI 视频 → 描述生成 → 选择生成预设 → 输入描述 → 开始生成
```

---

## 1.2 让图片动起来

### 什么时候用

已经有一张主体图片，希望保持图片主体并生成动作。

### 输入

- 恰好 1 张图片
- 文字描述动作、环境变化、镜头运动

### 不接受

- 2 张图片（应该使用“首尾画面过渡”）
- 多张参考（应该使用“保持人物 / 产品一致”）
- 视频作为首帧

### 演示

```text
图片：黑色智能手环产品图
描述：镜头缓慢环绕产品，屏幕亮起，保持产品结构不变。
```

---

## 1.3 首尾画面过渡

### 什么时候用

已经知道视频的开始状态和结束状态，需要生成中间过程。

### 输入

- 恰好 2 张图片：开始画面 + 结束画面
- 描述中间如何过渡

### 不接受

- 视频参考
- 第三张参考图

### 演示

```text
开始：汽车停在路边
结束：汽车驶入隧道
描述：汽车平稳起步并逐渐加速，镜头从侧后方跟随，自然进入隧道。
```

---

## 1.4 保持人物 / 产品一致

### 什么时候用

需要参考一个或多个主体的外观，例如人物、产品、服装、场景。

### 输入

- 1–5 个参考素材（当前普通 UI 限制）
- 图片或支持的视频参考
- 文字描述主体要做什么

### 和“人物一致预设”的关系

“多参考”是**素材能力**；“人物一致”是**创作策略**。

例如：

```text
生成方式：保持人物 / 产品一致
生成预设：人物一致
```

这两个可以同时使用，而且职责不同。

# 功能 2：生成预设 Recipe

生成预设解决的问题是：**这段视频应该按照什么创作目标来生成？**

Recipe 不等于模型，也不等于 Provider。

选择 Recipe 后会发生两件事：

1. 调整适合该场景的默认画幅 / 时长；
2. 提交任务时加入稳定的生成策略。

用户仍然可以修改画幅和时长。

---

## 2.1 通用镜头

### 用途

没有明确商业、人物一致或短视频要求时使用。

### 业务边界

- 不强制产品策略
- 不强制人物一致策略
- 不强制短视频节奏

### 演示

原始输入：

```text
一辆黑色跑车晚上经过城市街道
```

目标表达：

```text
黑色跑车在夜间城市街道平稳驶过，湿润路面反射霓虹灯光，镜头低机位侧向跟拍，车辆结构保持稳定，运动自然连续。
```

---

## 2.2 产品广告

### 用途

- 电商广告
- 新品展示
- 产品主视觉
- 商品动态展示

### 核心优先级

```text
产品结构稳定 > 产品颜色/材质稳定 > 一个清晰卖点 > 炫技镜头
```

### 不适合

纯剧情或需要大幅改变产品结构的创意。

### 演示

原始输入：

```text
黑色智能手环放在桌面上，做一个高级广告
```

建议操作：

```text
生成方式：让图片动起来
生成预设：产品广告
图片：产品原图
提示词：黑色智能手环放在桌面上，做一个高级广告
```

系统策略重点：

```text
保持产品结构、颜色、材质和标志稳定；镜头运动克制；避免产品边缘和文字畸变。
```

---

## 2.3 人物一致

### 用途

固定人物、数字角色、系列视频中的同一人物。

### 前提

必须使用：

- “让图片动起来”，或
- “保持人物 / 产品一致”。

文生视频没有人物参考，因此 UI 不允许选择该预设。

### 核心优先级

```text
人物身份 > 脸部 > 发型/年龄感 > 体型 > 主要服装 > 大幅动作
```

### 演示

```text
生成方式：保持人物 / 产品一致
生成预设：人物一致
参考图：女孩正面、侧面、全身照
描述：女孩走进咖啡店，在门口回头看镜头。
```

---

## 2.4 电影镜头

### 用途

品牌片、剧情镜头、氛围镜头、电影感 B-roll。

### 核心策略

- 一个短镜头只保留一个主要镜头运动
- 构图、景深、光线明确
- 不在 5–10 秒里塞进很多事件

### 演示

```text
男人在东京雨夜街头向镜头走来
```

预设重点：

```text
浅景深、真实低照度光影、稳定后退跟拍、动作连续。
```

---

## 2.5 短视频主镜头

### 用途

短视频开场、社媒主镜头、5 秒左右的高辨识度内容。

### 核心策略

```text
第一秒明确主体 → 只表达一个视觉重点 → 背景不抢主体 → 优先竖屏
```

### 不适合

慢节奏铺垫、复杂剧情、长镜头叙事。

# 功能 3：提示词智能增强

提示词智能增强解决的问题是：**用户知道自己想要什么，但不想学习提示词写法。**

## 它会做什么

只整理：

- 主体
- 动作
- 环境
- 镜头运动
- 光线 / 质感
- Recipe 已定义的稳定要求

## 它明确不会做什么

- 不切换生成方式
- 不增加或删除素材
- 不切换百炼 / 万镜一刻
- 不更换视频模型
- 不虚构品牌、人物身份、产品型号
- 不擅自增加剧情

## 执行逻辑

```text
百炼 API Key + Workspace 可用
        ↓ 是
Qwen 文本模型整理提示词
        ↓ 否 / 调用失败
本地 Recipe 模板整理
```

UI 会明确告诉用户当前使用的是 Qwen 还是本地模板，不会把本地模板伪装成 AI 调用。

## 演示

用户输入：

```text
黑色手环高级一点，镜头转一下
```

选择：

```text
生成方式：让图片动起来
生成预设：产品广告
```

智能增强后的目标表达类似：

```text
保持输入图片中的黑色智能手环结构、颜色和材质不变，产品位于画面中心，柔和轮廓光突出表带与屏幕质感，镜头缓慢进行小幅环绕，动作平稳克制，高端科技产品广告风格。
```

增强完成后，用户仍可手动编辑文字再提交。

# Recipe、Prompt、Provider 的关系示例

用户：

```text
我有一张黑色手环产品图，想做 5 秒竖屏广告。
```

正确流程：

```text
生成方式
让图片动起来
    ↓
Recipe
产品广告
    ↓
Prompt
“手环放在桌面上，镜头慢慢转一圈”
    ↓
可选 Prompt 智能增强
整理为更明确的单镜头描述
    ↓
Provider Router
根据设置决定百炼 / 万镜一刻
    ↓
具体视频模型
由 Provider 层自动选择
```

不要把这些概念合并成一个“AI 自动处理”黑盒，否则用户无法理解失败原因。

# 后续功能接入顺序

后续继续按同样原则推进。

## Phase 2：批量版本 + 生成队列

职责：**同一个创作意图生成多个候选结果。**

与 Recipe 的关系：Recipe 保持一致，版本之间只允许模型随机性或明确变体策略发生变化。

与任务中心的关系：每个远端任务仍是独立 Job；上层增加 Batch/Group 关系，不能把多个真实任务伪装成一个任务。

## Phase 3：结果继续创作

职责：**把一个已有结果作为下一次创作的起点。**

典型动作：

- 再来一个类似版本
- 以结果首帧继续生成
- 加入参考素材
- 修改提示词后重做

它不是“重试”。

**重试**：同参数再次提交。

**继续创作**：产生新的创作意图和新的父子关系。

## Phase 4：主体卡

职责：保存可复用的人物 / 产品身份素材。

主体卡不是普通素材文件夹。它必须有明确身份：

```text
主体 ID
├── 名称
├── 类型：人物 / 产品
├── 主参考图
├── 辅助参考图
└── 使用规则
```

## Phase 5：Retake / 局部重做

职责：只替换已有视频中的一个明确时间范围。

它不是完整重做，也不是普通 Video-to-Video。

# 新功能验收规则

今后每增加一个 AI 视频功能，至少同时具备：

1. 用户入口名称；
2. 解决什么业务问题；
3. 明确输入；
4. 明确输出；
5. 不做什么；
6. 与已有功能的关系；
7. 一个可照着操作的演示；
8. 失败时能告诉用户是素材、Recipe、Prompt、Provider 还是远端模型的问题。

没有满足以上条件的功能，不进入主界面。
