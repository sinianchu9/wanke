# Wanke 原生视频延长（Video Continuation）

本功能解决的问题是：**已有一段短视频，希望沿同一时间轴继续往后生成，并返回包含原片的更长完整视频。**

当前实现只接入已经核实的百炼 Wan 2.7 原生 Video Continuation 能力。

它不会用“参考视频再生成”冒充视频延长，也不会假设万镜一刻具备同样的原生能力。

## 1. 当前底层能力

Wanke 使用：

```text
model = wan2.7-i2v-2026-04-25
media.type = first_clip
media.url = 原视频云端 URL
parameters.duration = 最终总时长
```

这里最容易误解的是 `duration`。

它表示：

> **最终完整视频总时长**

不是：

> 在原视频后面额外增加多少秒

例如：

```text
原视频：5 秒
targetDuration：10 秒
```

含义是：

```text
原 5 秒 + 约 5 秒新生成内容 = 10 秒完整结果
```

不是：

```text
原 5 秒 + 10 秒 = 15 秒
```

## 2. 输入边界

当前 Wanke 服务端严格限制：

```text
原视频时长：2–10 秒
最终总时长：最多 15 秒
最终总时长 > 原视频时长
视频必须有可被百炼访问的 HTTP/HTTPS 云端 URL
百炼 API Key 必须已配置
```

当前 UI 只从已经成功生成、仍有云端结果 URL 的 Wanke 视频任务进入。

本机归档路径不能直接作为百炼远端输入。

## 3. 为什么独立成 video_extension Job

“视频延长”不是普通 `video_generation` 的一个隐藏开关。

Wanke 单独定义：

```text
JobKind = video_extension
```

原因：

- 输入语义不同：原视频是 `first_clip`；
- 时长语义不同：`duration` 是最终总时长；
- Provider 能力边界不同：当前只走百炼 Wan 2.7；
- 结果关系不同：延长任务是原结果的时间轴子任务。

任务中心会明确显示：

```text
视频延长源自：原任务
```

## 4. 与“结果继续创作”的区别

这是两个不同功能。

### 结果继续创作

```text
旧视频
  ↓
作为 reference_video
  ↓
输入新的创作要求
  ↓
生成另一条新视频
```

它强调：

> 参考旧视频的主体 / 风格 / 内容关系，再创作一条新的结果。

它不承诺时间轴无缝衔接。

### 视频延长

```text
旧视频
  ↓
作为 first_clip
  ↓
描述接下来发生什么
  ↓
沿时间轴继续生成
  ↓
返回包含原片的完整更长视频
```

它强调：

> 从原视频结束的位置继续往后发生。

因此：

```text
继续创作 ≠ 延长
```

## 5. 与“再来一个类似版本”的区别

“再来一个类似版本”复制原任务的创作输入，再独立生成一次。

它不会使用刚才生成的结果视频作为时间轴起点。

视频延长则必须选择一个具体成功结果作为 `first_clip`。

## 6. 与批量版本的关系

一个 Batch 可以有：

```text
版本 1/3
版本 2/3
版本 3/3
```

视频延长不是“延长整个 Batch”。

用户必须先选中一个具体结果，例如：

```text
版本 2/3
```

然后只延长这个版本。

这样来源关系明确，不会出现“一个延长任务到底延长哪条候选”的歧义。

## 7. 与 Recipe 的关系

视频延长不会重新把原 Recipe 的执行策略再拼一次。

原因：

- 原 Recipe 已经影响了 first clip 的画面；
- 延长阶段主要任务是保持时间、动作、场景连续；
- 再重复注入原 Recipe 可能让“延续”变成“重新设计镜头”。

所以延长 UI 只要求用户描述：

> 原视频结束之后，接下来发生什么？

原 Recipe 可以通过父任务血缘追溯，但不是当前 extension 请求的直接控制项。

## 8. 与主体卡的关系

如果原视频来自：

```text
人物卡 / 产品卡
  ↓
AI 视频生成
  ↓
成功结果
```

延长时不会再次把主体卡图片发送给模型。

身份连续性主要来自：

```text
first_clip 原视频本身
```

主体卡仍保留在父任务的来源血缘中。

这样不会把：

```text
first_clip + 一组主体参考图
```

混成未经官方边界验证的新组合。

## 9. 与 Provider Router 的关系

基础 AI 视频有：

```text
自动 / 强制百炼 / 强制万镜一刻
```

但视频延长当前是**功能专属 Provider 能力**。

所以：

```text
视频延长 → 百炼 Wan 2.7 原生 continuation
```

即使用户把“基础视频引擎”设置成“强制万镜一刻”，只要百炼 Key 已配置，视频延长仍明确使用百炼。

原因是：

> 基础视频 Provider 偏好，不应该让一个没有被核实支持 continuation 的 Provider 冒充延长能力。

如果百炼没有配置，UI/API 会明确提示，不自动回退。

## 10. 使用演示 A：5 秒延长到 10 秒

已有结果：

```text
5 秒视频
女孩推开咖啡店门并走进去
```

操作：

```text
1. 任务中心打开成功结果
2. 找到“延长这个视频”
3. 最终总时长：10 秒
4. 输入：女孩继续走到柜台，在柜台前停下并回头看向镜头，镜头保持平稳跟随
5. 点击“延长到 10 秒”
```

预期：

```text
原 5 秒内容
+
约 5 秒连续新内容
=
10 秒完整视频
```

## 11. 使用演示 B：10 秒延长到 15 秒

已有结果：10 秒。

```text
最终总时长：15 秒
```

表示最多再产生约 5 秒连续内容。

结果达到 15 秒后，不能继续作为下一次原生 continuation 的 first clip，因为当前 first clip 输入上限是 10 秒。

## 12. 不适合视频延长的需求

### 换背景

属于视频编辑。

### 换人物 / 换商品

属于视频编辑 / 主体替换。

### 只重做第 3–5 秒

属于 Retake / 局部重做。

### 想保持这个视频风格，但拍一条完全不同的新镜头

属于“结果继续创作”。

### 想再生成一个方向相同的随机候选

属于“再来一个类似版本”或批量版本。

## 13. 失败边界

### 原视频 URL 过期

百炼无法下载 first clip，会返回素材访问错误。

这是：

```text
输入素材失效
```

不是 Prompt 错误。

### 百炼 Key 未配置

不提交任务，不回退到万镜一刻。

### 原片超过 10 秒

UI 和服务端都会阻止。

### 最终时长小于或等于原片

服务端拒绝。

因为这不是延长。

### 最终时长超过 15 秒

服务端拒绝。

## 14. 任务与重试

视频延长任务是普通持久化 Job，因此拥有：

- 独立 task_id；
- queued / running / succeeded / failed；
- 自动轮询；
- 失败原因；
- 本机归档；
- 删除；
- 失败重试；
- parentJobId 来源关系。

失败重试仍然是“重新执行这次延长”，不会改写原成功视频。

## 15. 当前明确不做

本阶段不做：

- 自动剪裁 >10 秒视频后再延长；
- 多段自动串联成长视频；
- 原片中间插入镜头；
- Retake；
- 自动把多个 extension 拼成 Project；
- 用 reference-to-video 假装 continuation；
- 未核实情况下回退万镜一刻。

## 16. 验收标准

- [x] 独立 `video_extension` JobKind；
- [x] 使用 Wan 2.7 `first_clip`；
- [x] 服务端限制 source 2–10 秒；
- [x] 服务端限制最终总时长最大 15 秒；
- [x] UI 明确“总时长”而非“追加时长”；
- [x] 只从具体成功结果进入；
- [x] 有 parent/child 来源关系；
- [x] 与继续创作、批量版本、Recipe、主体卡、Provider Router 边界明确；
- [x] 页面内有使用说明和操作演示；
- [x] 不伪造万镜一刻 continuation 能力。
