# Wanke 视频生成 Phase 1

## 目标

第一阶段只集中力量提升“生成视频”这件事，不让用户承担模型选择、API 差异和素材规则。

用户只需要回答两个问题：

1. 我手里有什么素材；
2. 我想生成什么画面。

模型、API 路由、参考素材编号、时长兼容、任务查询和常见错误翻译都由 Wanke 处理。

## 用户入口

主界面只保留四种用户语言：

- **描述生成**：没有素材，直接描述想要的视频；
- **让图片动起来**：一张图片生成视频；
- **首尾画面过渡**：指定开始画面和结束画面；
- **保持人物 / 产品一致**：用多张图片或参考视频保持主体一致性。

默认：1080P、5 秒、单版本。画幅、时长、清晰度和任务名称收进“画面设置”，模型名和专家 JSON 不出现在普通生成流程。

### 本地图片直接使用

配置百炼直连后，单图、首尾帧和多参考图片都可以直接从电脑选择 JPG / PNG / WEBP，不需要先上传 OSS，也不需要理解 MediaId。

Wanke 不把 Base64 图片写入 SQLite：

```text
浏览器选择本地图片
        ↓
POST /api/video-inputs
        ↓
data/inputs/<uuid>.<ext>
        ↓
任务 request 只保存 wanke-input://... 引用
        ↓
真正提交模型时临时转 Base64
        ↓
重试仍可复用同一输入
```

单张本地图片限制为 10MB。用户主动移除图片时会清理未使用文件；删除任务时只有在没有其他重试/子任务引用时才清理；未提交就关闭页面留下的孤儿输入会在后续上传时清扫。

参考视频目前仍使用公网 MP4/MOV URL，因为当前直连模型的视频参考输入要求公网 URL。

## 自动路由

| 用户目标 | 自动模型 | 原因 |
|---|---|---|
| 描述生成 | `happyhorse-1.1-t2v` | 默认主生成模型 |
| 单图生成 | `happyhorse-1.1-i2v` | 默认主图生视频模型 |
| 首尾画面 | `wan2.7-i2v-2026-04-25` | 原生首帧 + 尾帧控制 |
| 纯图片多参考 | `happyhorse-1.1-r2v` | 强调人物 / 产品参考一致性 |
| 包含视频参考 | `wan2.7-r2v-2026-06-12` | 支持参考视频 |

多参考时 Wanke 自动补充模型需要的 Image / Video 引用语义和一致性约束，用户不需要学习 `[Image 1]` 等提示词格式。

为了让图片和视频混合参考的行为一致，普通界面统一限制最多 5 个参考素材；超过上限不会静默截断，而是明确阻止提交。

包含参考视频时，生成时长自动限制在 10 秒以内，避免用户提交后才收到模型参数错误。

## Provider 策略

`lib/video/provider.ts` 是应用层唯一的视频生成任务入口。

- 配置 `DASHSCOPE_API_KEY`：基础视频生成优先直连 Alibaba Cloud Model Studio；
- 公网素材不会因为存在旧 MediaId 而被强制绕回 Yike；
- 只有确实位于旧 Yike 私有素材空间的素材才需要兼容工作流换取临时可访问 URL；
- 没有百炼 Key、且输入仍可由旧接口处理时，自动使用兼容生成链路；
- 本地图片 Base64 只允许走百炼直连，避免误送给旧接口；
- 高级复刻、数字人口播、旁白、故事板等 Phase 1 不改，继续使用现有 Yike 工作流。

这样可以逐步替换底层能力，而不需要推倒已有任务中心、素材库、归档和高级工作流。

## 素材库策略

公网 HTTP/HTTPS 素材现在可以独立保存为 URL-only 资产，即使没有 Yike 凭证也可以用于基础视频生成。

如果扩展工作流凭证存在，Wanke 会尝试同时登记扩展媒资；即使该登记暂时失败，也不会阻止一个正常公网 URL 被保存并用于基础生成。

普通素材库不再要求用户理解 MediaId 或云端逻辑删除。基础本地图片直接在“AI 视频”页面选择；视频/音频/故事板等扩展素材上传仍保留原有扩展工作流能力。

## 配置

推荐新加坡 Model Studio：

```env
DASHSCOPE_API_KEY=
ALIYUN_MODELSTUDIO_WORKSPACE_ID=
```

如果未填写 Workspace ID，代码仍保留国际通用域名作为兼容路径。真实 Key、Workspace 和模型权限在首次生成时校验，不能因为环境变量存在就假定已经验证成功。

本地输入默认位于：

```env
WANKE_INPUT_DIR=./data/inputs
```

已有 Yike 凭证可以继续保留给扩展工作流：

```env
ALIYUN_ACCESS_KEY_ID=
ALIYUN_ACCESS_KEY_SECRET=
ALIYUN_REGION_ID=ap-southeast-1
```

不要把真实 Key 提交进仓库。

## 任务闭环

```text
用户选择目标 + 描述 + 素材
        ↓
provider-neutral prepare input
        ↓
video provider router
        ↓
HappyHorse / Wan / compatibility fallback
        ↓
task_id / JobId
        ↓
SQLite task center
        ↓
provider-aware auto polling
        ↓
result preview
        ↓
retry / local archive
```

单任务刷新、批量自动刷新和重试都经过同一个 provider router，避免不同 Provider 的任务 ID 被错误查询。

Model Studio 异步视频任务使用约 15 秒起步的轮询间隔，旧 Yike 任务保留原有自适应策略。云端结果 URL 会过期，任务中心会提示用户将满意结果保存到本机。

## 本轮 Bug 审查已处理

1. **素材准备仍固定依赖 Yike**：已改成 provider-neutral；公共 URL 不再触发 Yike 换签。
2. **批量刷新仍固定查询 Yike**：创建、重试、单任务刷新和批量刷新已全部统一走 `lib/video/provider.ts`。
3. **状态页把“配置 Key”误报成“连接成功”**：现在只显示“已配置”，真实权限首次生成校验。
4. **图生视频只检查数量、不检查素材类型**：后端强制单图模式必须是图片，首尾帧必须两张都是图片。
5. **参考视频 15 秒会被模型拒绝**：检测到视频参考后自动收敛到最多 10 秒。
6. **多参考超过上限被静默截断**：改为明确计数并阻止提交。
7. **任务中心泄露 Provider/模型工程信息**：普通结果和状态改成 provider-neutral 文案，技术信息只保留在折叠详情。
8. **Model Studio 查询过于频繁**：调整为约 15 秒起步，减少无意义查询。
9. **云端结果 URL 会过期但 UI 没提醒**：结果页明确推荐保存到本机。
10. **只配百炼时公网素材无法注册**：公网 URL 现在可以独立保存，不再强依赖扩展媒资登记。
11. **本地图片缺乏傻瓜入口**：新增本地图片直选、持久化引用、Base64 临时提交和安全清理。
12. **API 原始错误过于工程化**：常见 Key、权限、限流、额度、素材 URL 和参数错误已翻译成用户可执行的中文提示。

## 验证边界

本轮已按 Alibaba Cloud 当前官方 API 文档核对关键模型名、输入类型、参考数量、时长、Base64 图片输入、异步任务查询与结果有效期。

当前仓库没有 PR GitHub Actions workflow；本执行环境也无法直接访问 `github.com` 拉取分支，因此本轮不能声称已经实际运行 `npm run typecheck` / `npm run build`。

合并前仍需在真实运行环境完成：

```bash
npm install
npm run typecheck
npm run build
npm run doctor
```

随后用真实新加坡百炼 Key 对以下四条最小路径各做一次 smoke test：

1. 纯文字 → 5 秒 1080P；
2. 本地 JPG/PNG → 单图生视频；
3. 两张本地图片 → 首尾帧；
4. 多参考图片，以及一条带公网 MP4/MOV 的参考任务。

检查点：任务成功提交、自动轮询、结果预览、失败中文提示、复制参数重跑、本机保存。Key 只放 `.env.local`，不要提交到 GitHub。

## Phase 1 暂不做

- 不删除 Yike；
- 不重写高级复刻、数字人和故事板；
- 不引入 Wonder 作为生产依赖，等其可稳定集成后再增加 Provider；
- 不做完整 NLE 时间线；
- 不把底层模型参数暴露给普通用户。

下一步仍应集中在生成质量本身：真实 API smoke test、提示词增强、结果质量比较、模型路由 A/B 记录，以及在不重复收费的前提下增加安全自动降级策略。
